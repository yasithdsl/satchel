Project: Prepaid Agents. A Bitcoin custody setup for AI agents where no single device can steal the main funds, built for a Ledger-sponsored hackathon (theme: AI agents using Ledger as the trust layer).

The system has five parts. The vault is an offline device that holds the master seed and never signs anything. The signer is a separate offline device that signs transactions using only the specific child keys it is given for that payment, and is assumed to be potentially malicious. Envelopes are small prepaid budgets, each sitting on its own fully hardened key, which can be handed to an AI agent so it can spend without asking. The Ledger is the human approval device: the vault only releases keys when it sees a Ledger signature over a plain-English plan. The shopping agent is the user-facing product and talks to a demo marketplace.

Key decisions that every part must follow:
- All key derivation is fully hardened at every level. Receive keys use m/84'/1'/0'/0'/i', change keys use m/84'/1'/0'/1'/i', and envelope keys use m/84'/1'/0'/2'/i'. Hardening matters because with normal derivation, one leaked child key plus the xpub reveals the whole wallet.
- Addresses are native SegWit (P2WPKH) on Bitcoin regtest only. Never write code that can touch mainnet.
- The vault never signs. Only the signer and the agent's envelope wallet sign.
- All honest signing uses one shared deterministic signing function (RFC6979 nonces) from the core library, so the vault can recompute any honest signature byte for byte.
- Security decisions are made by deterministic code, never by the LLM. The agent only requests actions.
- Every payload that crosses a device boundary (vault, signer, Ledger approver, laptop) is serialised in a QR-ready format, even though the demo moves it over local HTTP. The UI shows these as QR codes.
- Every significant action emits an event to the shared event stream so the x-ray UI can show it.

Stack: Python 3.12 managed with uv for the core library, vault, signer, envelope wallet, marketplace and agent. embit for Bitcoin primitives. FastAPI for small local services. bitcoind in Docker for regtest. The Anthropic Python SDK for the agent. A small Node/TypeScript service using Ledger's Device Management Kit with the Speculos emulator for Ledger approvals. Next.js for the web UI.

Working style: make small, reviewable changes. Write tests for anything security-relevant. Prefer clear code over clever code. When a ticket is done, stop and summarise what you built, which files changed, how to run and test it, and anything you were unsure about.

Commands:
- `uv sync` installs the whole workspace (Python packages are `satchel_core`, `satchel_vault`, `satchel_laptop`, `satchel_signer`, `satchel_agent`, `satchel_marketplace`).
- The vault simulates an air-gapped device: it never imports network code or signing functions (enforced by `vault/tests/test_vault_boundaries.py`). The online `laptop` service reads vault payloads over HTTP and adds chain data.
- `uv run satchel-signer serve` runs the signer (port 8002); it never stores keys or broadcasts (enforced by `signer/tests/test_signer_boundaries.py`). Vault `POST /verify` (in `satchel_vault/verification.py`, the only vault module allowed to call `sign_digest`) must pass before any broadcast. The demo-only random-nonce signer (`satchel_signer/random_nonce.py`, flag `SATCHEL_SIGNER_RANDOM_NONCE` or `POST /demo/random-nonce`) is the only other file allowed a signing primitive (`tests/test_signing_path.py`); it must never be used outside the signer.
- Ledger approvals: `approver/` (Node/TypeScript, pnpm, DMK + Speculos; deps must be ≥7 days old, enforced by `minimumReleaseAge`). `cd approver && pnpm fetch-app`, `docker compose --profile ledger up -d speculos` (API/UI on 127.0.0.1:5001), `pnpm start` (port 8003), `pnpm typecheck && pnpm test`. DMK skills live in `.agents/skills/`; read them before touching approver code. The plan-text format is shared with the vault via `fixtures/approval_text_vectors.json` — change both sides together. Keys leave the vault only via `satchel_vault/release.py` after `approvals.validate_approval`. Tests marked `speculos` need Speculos running.
- Coordinator flows live in `laptop/` (`grant.py`, `spend.py`, `main_funds.py`); every hop goes through `flows.FlowRecorder` (event + QR-ready payload, WIFs redacted). Broadcasting from the laptop must go through `broadcast.broadcast_verified`, which requires a vault verification pass for the exact transaction (txid and wtxid); a test forbids other `.broadcast(` calls in laptop code. End-to-end flows: `tests/test_coordinator_flows.py` (needs bitcoind and Speculos).
- `uv run satchel-marketplace serve` runs the demo store (port 8004). Catalogue is `marketplace/src/satchel_marketplace/catalogue.json` (prices as BTC strings, fixed $100k/BTC demo rate, validated at load). Payments go to fresh addresses from the node's `merchant` wallet (a demo third party, never project keys); orders are paid at 1 confirmation.
- Shopping agent: `agent/` (`satchel-agent serve`, port 8005). System prompt is `satchel_agent/prompts.py` and tool definitions are `TOOL_DEFINITIONS` in `satchel_agent/tools.py`; change them deliberately, not incidentally. The agent must never import `satchel_vault`, `satchel_signer` or `satchel_laptop` or use `MasterKey` (enforced by `agent/tests/test_boundaries.py`); it reaches the laptop flows only over HTTP. The done-criterion test `tests/test_agent_shopping.py` uses a scripted model; `live_llm`-marked tests need `ANTHROPIC_API_KEY`. The simulated-compromise demo (`satchel_agent/compromise.py`, `/demo/*` routes, only with `SATCHEL_AGENT_DEMO_CONTROLS=1`) is a deterministic script, never the model; its e2e proof is `tests/test_compromise.py`.
- Demo envelope sizes are `DEMO_ENVELOPE_BUDGETS` in `satchel_vault/vault.py` (200,000 / 200,000 / 100,000 sats = $200 / $200 / $100 at the catalogue rate: scene 1 shops with the first $200, scene 2 drains the fresh second $200, scene 3 outgrows the $100); allocate them with `satchel-vault allocate --demo` or `Vault.allocate_demo_envelopes()`, and use the latter in demo-style e2e tests.
- Demo stack ports: laptop 8000, vault 8001, signer 8002, approver 8003, marketplace 8004, agent 8005, x-ray 8006, Speculos 5001, web 3100 (port 3000 is taken on the dev machine). `uv run scripts/demo_reset.py` recreates the regtest chain, sets up the vault from the fixed `DEMO_SEED` (`Vault.setup_with_demo_seed`, demo only), funds main funds and the demo envelopes, and starts every service detached (PIDs in `.satchel/run`, logs in `.satchel/logs`); `--stop` stops them. `uv run scripts/demo_scenarios.py` plays the three demo scenarios against the running stack with real Claude and scripted Ledger decisions via the approver's Speculos automation endpoints (the reset starts the approver with demo automation on). The done criterion for demo work is reset + scenarios passing twice in a row.
- X-ray backend: `xray/` (`satchel-xray serve`, port 8006) tails the event log(s) (`SATCHEL_XRAY_EVENT_LOGS` or `SATCHEL_EVENT_LOG`), enriches events (diagram nodes, hop labels, QR parts read from the laptop's flow files, vault-block alerts, simulation flags) and serves `GET /events` (SSE), `GET /state`, `POST /demo/random-nonce`, `POST /demo/mine`, and `POST /demo/reset` (demo only; enabled when the demo stack sets `SATCHEL_XRAY_RESET_SCRIPT`, reruns `demo_reset.py` detached, logs to `.satchel/reset.log`). Web UI: `web/` (Next.js, pnpm, `minimumReleaseAge` enforced): `pnpm typecheck && pnpm test && pnpm build && pnpm e2e` (e2e mocks the backends, port 3200). Shopper mode (chat) is the default; the X-ray switch shows the caption bar, device strip, numbers row and Ledger takeover; P opens the presenter drawer. Every event type needs a deliberate caption or a deliberate silence in `web/lib/caption.ts` (enforced by `web/test/caption.test.ts`). Neither view may show transaction or order ids, addresses, keys, raw sats or error codes; the chat never shows QR codes. The x-ray proxies the Ledger (`/ledger/screenshot`, `/ledger/screen-text`, `/ledger/finger`, `/ledger/approve|reject`) so the browser never talks to Speculos directly; approve/reject failures come back as `{detail: {reason}}` (`nothing_pending`, `busy`, `automation_off`, `error`) and the approver's demo buttons refuse with `nothing_pending` when no request is on the device. `pnpm e2e:real` drives all three scenes through the presenter drawer at 1920x1080 against a freshly reset stack with real Claude, checks the visible text and that the x-ray never scrolls, saves the big moments to `docs/screenshots/`, and fails on any console warning, failed request, or `Traceback`/500 in `.satchel/logs`; run `pnpm build && pnpm start` first and make sure no stale `next` server holds port 3100 (or use `SATCHEL_REAL_URL` with an origin allowed via `SATCHEL_WEB_ORIGINS`).
- Run `uv run scripts/demo_reset.py --stop` before `uv run pytest`: the demo approver holds the Speculos session and the `speculos`-marked tests fail while it runs. `RegtestNode.list_unspent` uses `scantxoutset`, which bitcoind runs one at a time; it serialises and retries, so keep using it rather than calling `scantxoutset` directly.
- `uv run satchel-vault setup|allocate|serve|reset` runs the vault (passphrase from `SATCHEL_VAULT_PASSPHRASE` or a prompt); `uv run satchel-laptop serve` runs the coordinator; `uv run scripts/fund_envelopes.py` funds allocated envelopes from the faucet. State lives under `.satchel/`.
- `uv run scripts/regtest.py up` starts regtest bitcoind in Docker and makes sure the faucet wallet has spendable coins. `down` stops it; `docker compose down -v` wipes chain state.
- `uv run scripts/regtest.py fund <bcrt1 address> [sats]` funds an address and mines a confirming block; `unspent <address>...` lists its UTXOs.
- `uv run pytest` runs all tests. Tests marked `regtest` skip when the node is down.
